1. PROJECT OVERVIEW & ARCHITECTURE
====================================================================================================

1.1 PROJECT INTRODUCTION
- Project Name: TideTrace
- UI Console Title: "NTRO Oil Spill Attribution Console"
- Problem Statement Code: SIH26143
- Ministry / Organisation: National Technical Research Organisation (NTRO)
- Category & Theme: Software | Disaster Management / Space Technology
- Core Objective:
  Samundar mein oil spills (tel ke risaav) ko Sentinel-1 SAR (Synthetic Aperture Radar) satellite
  imagery ke zariye detect karna, metocean (ERA5 wind + ocean currents) physics ke dwara
  slick ko backward trace karke uske origin point aur time ka pata lagana, future flow predict karna,
  aur historic AIS (Automatic Identification System) maritime traffic data ko correlate karke
  spill ke liye jimmedar vessel (jahaz) ko rank aur attribute karna with solid evidence and reason codes.

1.2 NON-NEGOTIABLE ARCHITECTURAL PRINCIPLE: "THE OFFLINE BOUNDARY"
- Judge / Demo time par internet unplugged (airplane mode) hone par bhi poora system 100% chalna chahiye.
- Rule:
  * Network access sirf aur sirf PREPARATION lane (`scripts/`) mein allow hai, jo demo se pehle
    ek baar execute hoti hai aur data `data/` directory mein freeze/cache karti hai.
  * Application runtime (`app/`) 100% pure local files read karta hai. Runtime ke dauran koi bhi
    socket, live API call ya DNS lookup nahi hota (ise unit tests mein socket-block karke verify kiya gaya hai).
  * No Docker, no Cloud mandatory dependency, no CUDA hard requirement (CPU par bhi chalta hai).

1.3 10-STEP COMPLETE PIPELINE (What happens when you click "Run Analysis")
  SAR Chip (VV/VH GeoTIFF)
         |
         v
  [1] DETECT       : UNet++ Deep Learning segmentation, ya phir -22 dB baseline detector
                     -> Returns Oil Polygons aur Look-alike Polygons.
         v
  [2] CHAR         : Local AEQD (Azimuthal Equidistant) projection mein metric characterisation
                     -> Area (km2), length, width, perimeter, orientation, compactness, centroid.
         v
  [3] EO           : Sentinel-2 optical chip comparison (agar optical data available ho).
         v
  [4] METOCEAN     : Cached ERA5 10m wind aur CMEMS / Open-Meteo surface currents ka spatial & temporal interpolation.
         v
  [5] HINDCAST     : RK2 (Runge-Kutta 2nd Order) Lagrangian backward ensemble (50 particles)
                     -> Slick ke andar se particle release karke backward drift run hota hai.
                     -> Calculates: Origin Zone Polygon, Origin Time, Zone Radius.
         v
  [6] FORECAST     : Same RK2 integrator forward direction mein run hota hai
                     -> Calculates: Future dispersion cone, threatened bounding box, coast impact flag.
         v
  [7] AGE_PROXY    : Origin time aur satellite pass time ke beech ke ghante (drift-time proxy).
         v
  [8] AIS          : Origin zone aur time window ke aas-pass SQLite store se vessel positions fetch karta hai.
         v
  [9] FILTER       : Spatio-temporal funnel jo non-relevant traffic ko filter out kar deta hai.
         v
  [10] SCORE       : 5 sub-scores compute karke vessel leaderboard banata hai:
                     - Proximity Score (30%)
                     - Time Difference Score (20%)
                     - Behavior Anomaly Score (25% - e.g., AIS gaps, sudden speed/course change)
                     - Vessel Type Prior (15% - Crude Tanker = 1.0, Cargo = 0.5, etc.)
                     - Trajectory Alignment (10%)
                     - Multiplied by Track Confidence Multiplier (penalises dead reckoning).
                     -> Output: Ranked Suspects with exact reason codes.

1.4 TECH STACK
- Backend Runtime: Python 3.11+
- Web Framework: FastAPI + Uvicorn
- Data Validation: Pydantic v2
- Numerics & Math: NumPy (Core mandatory dependency)
- Spatial & Geometry: SciPy (morphology/speckle), PyProj (projection), RasterIO (GeoTIFF), Shapely
  (Note: Agar SciPy, PyProj, RasterIO install na ho, to pure NumPy/Python fallbacks inbuilt hain!)
- ML Framework: PyTorch + segmentation-models-pytorch (UnetPlusPlus, timm-efficientnet-b0)
  (Note: ML framework na hone par inbuilt pure NumPy/SciPy fallback baseline detector chalta hai!)
- Database: SQLite (MarineCadastre standard schema)
- Frontend UI: Vanilla HTML5, Modern CSS, Vanilla JavaScript, Vendored Leaflet 1.9 (No React, no build step, no CDN needed).

3.1 HOW TO RUN TESTS
TideTrace ke pas 126+ automated unit and integration tests hain jo offline behavior ko verify karte hain.

Poora test suite run karne ke liye:
```bash

```

Detailed / Verbose output dekhne ke liye:
```bash
python -m pytest tests -v
```

3.2 KEY TEST FILES EXPLAINED

1. `tests/test_pipeline_offline.py`
   - Airplane Mode Verification Test.
   - Yeh test Python ke `socket.socket` ko monkeypatch karke network access block kar deta hai.
   - Uske baad `/api/run` ko call karta hai. Agar koi bhi internal function internet access karne
     ki koshish karega to test turant FAIL ho jayega.

2. `tests/test_advection.py`
   - Physical Drift Physics Integrity.
   - Verifies: 1 m/s current for 1 hour moves particle exactly 3.6 km East.
   - Backward integration exactly forward integration ko undo karti hai.
   - Wind speed factor exactly 3% (0.03) apply hota hai.

3. `tests/test_geo_centroid.py`
   - Georeferencing & Geometry.
   - Verifies polygon UTM-to-WGS84 affine transformation accuracy (< 1e-4 degrees).
   - Area (km2), perimeter, orientation aur centroid calculations accurately match.

4. `tests/test_ais_gap.py`
   - AIS silence / Dark vessel detection.
   - 30 minute se bada silence period gap flag karta hai.
   - Origin zone ke paas gap hone par suspicious behavior score inflate hota hai.

5. `tests/test_scoring.py`
   - Multi-factor attribution algorithm tests.
   - Proximity, time, behavior anomaly, type prior, aur confidence formula test karta hai.
   - Proves: High-confidence observed vessel outranks heavily dead-reckoned vessel.

6. `tests/test_offline_boundary.py`
   - AST (Abstract Syntax Tree) code scanner.
   - `app/` ke har Python file ko scan karta hai aur check karta hai ki koi bhi network library
     (requests, urllib, httpx, boto3, etc.) runtime path par import na ho rahi ho.

7. `tests/test_conformance_fixes.py`
   - Edge case robustness (e.g., uniform clean water detection, multi-threading race conditions
     during model loading, retention cleanup of old jobs).

```bash

python scripts/build_synthetic_ais.py --all
```

http://127.0.0.1:8000

6. MACHINE LEARNING (ML) DEEP DIVE
====================================================================================================

6.1 KAHA HAI ML? (FOLDER STRUCTURE)
ML code base in folders mein divided hai:
- `app/ml/`                : Core inference, architecture builder, aur baseline fallback
  * `app/ml/model.py`      : UNet++ model definition, PyTorch dynamic loading & checkpoint IO
  * `app/ml/infer.py`      : Tiled 512x512 inference, cosine-tapered stitching, radiometry check
  * `app/ml/fallback.py`   : Inbuilt physics-based Sigma0 dark-patch baseline detector (Zero PyTorch!)
  * `app/ml/dataset.py`    : Zenodo SAR tile preprocessor & normalisation
  * `app/ml/train.py`      : Kaggle training script with soft Dice + cross-entropy loss
- `models/`                : Saved checkpoints folder
  * `models/oil_unet_best.pt` : Pre-trained UNet++ model weights (~78 MB, download via hf_sync)
  * `models/oil_unet_best.report.json` : Validation metrics & IoU benchmark report
- `scripts/`               : ML sync & data prep
  * `scripts/hf_sync.py`   : Hugging Face dataset & model sync
  * `scripts/build_kaggle_kernels.py` : Kaggle P100 training notebook builder

6.2 MODEL ARCHITECTURE & SPECS
- Model Type: Segmentation Network
- Architecture: `UnetPlusPlus` (nested dense skip connections)
- Backbone / Encoder: `timm-efficientnet-b0` (ImageNet pretrained weights)
- Input: 512 x 512 tiles, 3 channels (Channel 0: VV dB, Channel 1: VH dB, Channel 2: VV repeated)
- Output Classes (3 classes):
  * Class 0: Sea (Clear water)
  * Class 1: Look-alike (Algal bloom, biogenic film, low wind)
  * Class 2: Mineral Oil Slick (Crude oil spill)
- Performance on Zenodo Validation Set:
  * IoU_oil: 0.8891
  * IoU_sea: 0.9822
  * mIoU: 0.9356
  * Water called oil (False positive): 0.0106 (<= 2% hard ceiling)

6.3 TILED INFERENCE & COSINE TAPER STITCHING (`app/ml/infer.py`)
- Full satellite SAR scene 2048 x 2048 pixels ki hoti hai.
- Agar poori 2048x2048 image ek sath GPU/CPU par feed ki jaye to memory OOM crash ho sakti hai.
- TideTrace ise overlapping 512x512 tiles mein cut karta hai.
- Seams (borders) par artifacts avoid karne ke liye Cosine-Tapered Stitiching use hoti hai jisse
  probability maps smoothly blend ho jate hain.

6.4 THE SECRET WEAPON: ZERO-TORCH FALLBACK BASELINE (`app/ml/fallback.py`)
- Project creators ne bohot smart engineering ki hai:
  Agar server par PyTorch (`torch`) ya checkpoint file present NAHI hai, to code crash nahi hota!
- Automatic Fallback: System turant `app/ml/fallback.py` activate karta hai.
- Yeh method SAR physics par chalta hai:
  1. Boxcar multi-look speckle reduction filter in linear power domain.
  2. Sigma0 -22 dB adaptive thresholding.
  3. Morphological opening and closing.
  4. Contrast against local sea backscatter (> 3.5 dB) aur boundary compactness (< 0.62) se
     oil aur look-alike ko classify karta hai.
- Yeh pure NumPy + SciPy par chalta hai aur sirf ~15 MB RAM leta hai!

7. RENDER DEPLOYMENT & FREE TIER CRASH ANALYSIS (CRUCIAL SECTION)
====================================================================================================

7.1 THE RENDER FREE TIER PROBLEM (DEEP TECHNICAL ANALYSIS)
Aapka concern bilkul sahi hai: "Render ke free tier par ML deploy karenge to bohot heavy ho jayega
aur Render free wala work nahi karega."

Samjhiye Render Free Tier ki limitations kya hain:
1. RAM Limit: Exactly 512 MB RAM (Hard Limit).
2. CPU: 0.1 vCPU (Shared, throttle hota hai).
3. Inactivity Spin-Down: 15 minute tak traffic na aane par service band (sleep) ho jati hai.
4. Disk: Ephemeral (restart hone par temporary files gayab).

Kyu crash hota hai standard PyTorch ML app Render Free Tier par?
- Standard `torch` wheel + `segmentation-models-pytorch` + `torchvision` install karne par
  disk size 1.5 GB se 2.5 GB cross ho jata hai.
- Python process jab `import torch` aur model load karti hai, to baseline RAM usage hi
  250 MB se 350 MB chali jati hai.
- Jaise hi koi user `POST /api/run` dabata hai aur NumPy arrays 2048x2048 images ko memory mein
  expand karte hain, memory 512 MB exceed kar jati hai.
- Result: Render ka Linux kernel process ko `SIGKILL` (Exit Code 137: Out Of Memory) dekar
  service crash kar deta hai!

7.2 HOW TIDETRACE SOLVES THIS: THE WORKING ARCHITECTURE FOR RENDER
TideTrace ko pehle se hi aise design kiya gaya hai ki bina PyTorch ke bhi full system chalta hai!

HUMARE PAAS 3 DEPLOYMENT STRATEGIES HAIN:

----------------------------------------------------------------------------------------------------
STRATEGY 1: PURE LIGHTWEIGHT DEPLOYMENT ON RENDER (RECOMMENDED - 100% RELIABLE)
----------------------------------------------------------------------------------------------------
- Concept: Render Free Tier par hum PyTorch ko install hi NAHI karenge!
- Hum TideTrace ka Lean Stack use karenge:
  FastAPI + Uvicorn + Pydantic + NumPy + SciPy + PyProj + RasterIO.
- Slick Detection Inbuilt Physics-Based Baseline Detector (`app/ml/fallback.py`) se hogi.
- RAM Consumption: Sirf 70 MB - 110 MB RAM! (Render ke 512 MB limit se bohot neeche!).
- Advantage:
  * Zero OOM crashes.
  * Fast cold-start (under 10 seconds).
  * Har endpoint (Detect, Geometry, Metocean, Backward Hindcast, Forward Forecast, AIS Join,
    Ranked Suspects, HTML Report, Leaflet Console) 100% perfectly working rehta hai!

----------------------------------------------------------------------------------------------------
STRATEGY 2: DECOUPLED HYBRID ARCHITECTURE (BEST IF UNET++ DEEP LEARNING IS MANDATORY)
----------------------------------------------------------------------------------------------------
- Concept:
  1. Frontend Console + FastAPI Backend + Physics + AIS -> Render Free Tier (Lightweight).
  2. Heavy PyTorch UNet++ Model -> Hugging Face Spaces (FREE tier provides 16 GB RAM CPU or T4 GPU!).
- Render se `/api/detect` call HuggingFace Space ke REST endpoint ko forward hoti hai.
- Cost: Zero (Dono free tiers use hote hain without memory crash).

----------------------------------------------------------------------------------------------------
STRATEGY 3: MINIMAL CPU-ONLY PYTORCH ON RENDER (SINGLE WORKER TUNED)
----------------------------------------------------------------------------------------------------
- Agar aapko single service mein hi model chalana hai:
  * `torch --index-url https://download.pytorch.org/whl/cpu` (no CUDA libraries, 150MB wheel).
  * Uvicorn ko `--workers 1` par chalana mandatory hai taaki memory multiply na ho.
  * Environment variable `MALLOC_TRIM_THRESHOLD_=100000` set karein memory release ke liye.
  * Phir bhi peak usage par 420-480 MB ja sakta hai, isliye Strategy 1 sabse best aur stable hai.

  (Explanation: Yeh dependencies install karega aur test synthetic scenes generate kar dega taaki
  fresh container par turant run ho sake.)

- Start Command:
  ```bash
  uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 1
  ```
  (IMPORTANT: `--workers 1` rakhna jaroori hai! Multiple workers karenge to RAM 512 MB exceed kar jayegi.)

- Instance Type: Select **"Free"** (0.1 CPU, 512 MB RAM).

Key                                  | Value

`TIDETRACE_KEEP_JOBS`                | `50`

(Kyu chahiye yeh variables?
- `PYTHON_VERSION=3.11.9`: Render by default Python 3.14 ya 3.12 use kar sakta hai jisme kuch C-extensions fail ho sakti hain. 3.11 rock-solid stable hai.
- `TIDETRACE_OFFLINE=1`: Ensures ki server runtime mein koi unexpected outbound request na kare.
- `TIDETRACE_KEEP_JOBS=50`: Disk space ko clean rakhta hai taaki container bhar na jaye.)
